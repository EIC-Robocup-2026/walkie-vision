# ADR-0005: Use CUDA 12 builds that cover sm_75 and sm_120

<!-- --8<-- [start:body] -->
**Status:** Accepted · **Date:** 2026-10-19

**Context**

The development laptops have an RTX 2060 (`sm_75`). The robot is expected
to have an RTX 5090 (`sm_120`): walkie-ros's `yolo_node.py` names it, and
its robot image builds for `TORCH_CUDA_ARCH_LIST=12.0`. Nobody has checked
the robot's GPU or its driver yet.

A CUDA library runs on a GPU only if it holds machine code (SASS) for that
GPU, or PTX that the driver can compile for it. `cuobjdump` on the installed
wheels shows:

- torch 2.11.0 and torchvision 0.26.0 from the CUDA 12.8 index have SASS
  for `sm_75` and `sm_120`. torchvision 0.26 to 0.28 from the CUDA 12.9
  index stop at `sm_90`, with no PTX, so `torchvision.ops.nms` fails on
  `sm_120`. The 12.8 index has no torch newer than 2.11.
- `onnxruntime-gpu` 1.26 is the last CUDA 12 release. Its CUDA provider has
  SASS up to `sm_90a` and PTX for `compute_90`. On `sm_120`, the driver
  compiles each module from PTX the first time a session uses it. All 230
  modules took 22 minutes with `ptxas` 12.8 on one laptop core. The result
  is cached in `~/.nv/ComputeCache` (0.33 GiB, under the 1 GiB default
  limit), and a driver update empties the cache.

CUDA 12.8 builds need an R570 or newer driver on an RTX 50-series GPU.
CUDA 13 builds need R580 or newer.

**Decision**

- torch 2.11.0 and torchvision 0.26.0 from the CUDA 12.8 index.
- `onnxruntime-gpu` `>=1.26.0,<1.27`, with its `cuda` and `cudnn` extras, so
  that it uses the same `nvidia-*-cu12` wheels as PyTorch.
- No system CUDA. The robot needs an NVIDIA driver R570 or newer.
- `pixi run check-env` checks the GPU code in every CUDA library against the
  GPU it runs on (`c01_fatbins`). Run it after the install and after every
  driver update, so the compile cache is full before a test.

**Consequences**

- One environment runs on both GPUs.
- PyTorch stays at 2.11 until the environment moves to CUDA 13, and that
  needs an R580 driver on the robot.
- The first ONNX Runtime run on the robot after an install or a driver
  update is slow. If it is too slow, the options are ONNX Runtime's TensorRT
  provider (its libraries are not installed), ONNX Runtime 1.27 or newer on
  CUDA 13, or running the face models through PyTorch.
- The robot's GPU and driver must be checked before the competition.
- `torch` and `torchvision` move together, and only after `check-env`
  passes on the new pair.
